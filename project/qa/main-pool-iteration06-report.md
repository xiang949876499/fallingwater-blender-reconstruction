# 第六轮泳池连接诊断与第七轮最小修复

**北侧误封墙可以修正；原 ADJ017 不能继续作为普通干步行连接。** 原图支持两组分别通向泳池的台阶，但没有证明它们之间存在与梯脚同高、连续可走的环池干道。撤销该推导边不等于把失败改写为通过。

实际查看了 main04 原始 TIFF 的局部裁切，以及 main03 地下平面与 main09 立面的已保存 JPEG。裁切与来源、原图像素框、哈希在 `main-pool-iteration06-sources.json`。主图为 `main-pool-iteration06-plan04.png`，带分析坐标格网的版本为 `main-pool-iteration06-plan04-grid.png`；蓝线是分析辅助线，不是原图尺寸线。

main04 的石砌北缘在 source x≈626–628、y≈376 结束。main03 在相应位置画出向北凹入的台阶区，实墙不延伸到 x700。当前模型 `MAIN_B_pool_wall_0` 却沿 y376 从 x533 连到700，封住这一凹口。其实际网格为 X10.7944…19.5452、Y8.5684…8.8484、Z−2.50…−1.97m，台阶落脚层上方实挡约0.53m。

## 泳池边带不能直接认成干通道

main04 东侧石带约 source x695…706，南侧约 y419…428。平面线形首先证明池缘石构造，不能单独证明其顶面与台阶脚处同高或具备普通步行用途。该高度关系、池体水面与梯脚准确标高仍为 C/U。

tour 原东侧绕行线 X19.126m 对应 source x692，位于原图东石带以内约0.13–0.16m；它依赖当前模型偏宽的甲板支承。模型东池墙又位于 source x700、高出甲板0.53m，占据部分原图石带。因此，“当前网格能沿东南侧通过”不等于“源图证明有这条干路”。本次没有拓宽、增设或抬高任何环池甲板，也没有删东墙/南墙让路线通过。

## 已实施的最小候选修复

只把 `MAIN_B_pool_wall_0` 终点从 source (700,376) 改为 (628,376)，保留 (533,376) 起点、厚度、标高、材质。保留段世界坐标为 (10.7944,8.7084)→(15.7724,8.7084)m。终点取 main03/04 相互对应的约值，图形定位误差按 C±0.12m记录，不新增可读尺寸锚点。原东墙、南墙、池底、水、甲板和两组台阶均未改。

泳池的空间多边形仅修正为包含北凹口与池缘的**检查区包络**，显式标记 `walkable_polygon=False`。其记录 Z−2.50m 表示现有模型的池口落脚层，不是测得的池底高度；水面仍记录为现有模型 Z−2.70m。没有将整个多边形作为可行走地面。

`MAIN_L1_LOGGIA→MAIN_L1_TERRACE_E` 的旧干步行边已从有效邻接列表撤销，并保存在 `retracted_adjacency`，状态为 `SOURCE_UNSUPPORTED_AS_DRY_WALKEDGE`。旧 iteration06 ADJ017 仍为历史 FAIL。主屋有效邻接数由40变为39，数量不构成验收目标。

正确的访问解释是：

- Entry↔Loggia；Loggia 下梯可到东北侧池口观察，不能经整个泳池节点继续组合为干路。
- Entry↔Living↔East Terrace，客厅原有玻璃门提供合法入口。
- East Terrace 的另一组下降台阶保留，可单独检查其西侧池边端点；没有声明西端与东北端之间是普通干通道。
