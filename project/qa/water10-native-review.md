## 数据完整性、坐标与单位

读取规则为 config/data/mesh/secondary 四件齐全且至少 8 秒未变；烘焙进行时还要求已有更高完整帧。gzip CRC/长度、VDB 读取及读取前后大小/mtime 均核对，最后一帧在根监控退出后才读。48 帧都有独立 [frame JSON](water10-native-frame0048.json) 与对应 NPZ；没有读取半写帧。首批审计 numpy int64 JSON 序列化失败在读帧前发生，失败日志保留；后续 1–47 与最终 48 读取完成。

实际网格 **320×307×37**，单元 **0.075000003m**；求解域原点 (-16.0000005, -17.0125004, -7.7124999)，最大 (8.0000005, 6.0125005, -4.9374998)。这包含为了统一格距而与作者盒体边界相差 1.25cm 的 Y/Z 对齐，不把作者坐标直接当求解网格。

BOBJ→世界坐标由保存场景实际求值顶点拟合，约 24I 加中心 (-4, -5.5, -6.325)，最大误差 1.35µm。VDB velocity 为 staggered MAC 网格，half float / blosc；phi 元数据覆盖 3,634,880 格。粒子实际输出是 VDB `ptdataidx32`，虽然保存 RNA 的 particle format 为 UNI；以实际文件为准。[mapping](water10-native-mapping.json)、[probe](water10-native-probe.json) 保存原始依据。

内部时间换算由本次 CRC 通过的 config T 差 / scene 秒差得到 **2.499999754 内部时间/秒**，乘实际格距得到 **0.187499989 m/s 每原始 MAC 单位**。这是本次缓存测量，不是通用“乘 2.5”假设。以源内部独立速度核对：作者速度 (-1.50314, -1.00527, -6.69482)m/s，frame5–48 原生中位数 (-1.50586, -1.00159, -6.90820)m/s，向量相对差中位数 **3.08%**。垂直差可受重力和源覆盖时序影响；没有把它当作精确源速度强制相等，也没有用作者 Q 校正速度比例。

## 原生源下通量与未匹配的上游供给

在 z−5.62、−5.64、−5.68 三个水平面用同坐标 MAC 垂直速度与 phi<0 8×8 子格面积求积分，向下为正。主平面 z−5.64 的 frame5–48 全平面通量中位数 **0.621130m³/s**，p05–p95 **0.507977–0.785767m³/s**；作者新设计为 **0.2994137m³/s**，偏差 **+107.45%**。三高度中位数为 0.616854 / 0.621130 / 0.632167m³/s。

主平面同时保留固定水束窗口 X[0.3,1.5], Y[−2.7,−1.65]：窗口中位数 **0.621349m³/s**，p05–p95 **0.559402–0.674060**，积分 **1.204712m³**；全平面积分 **1.223980m³**。窗口外瞬时绝对通量最高 0.212458m³/s，可能含池面/飞溅穿越；所以不能把全部平面每个时刻都称为纯源注入。窗口也不是粒子来源追踪，但限制窗口后约 2.07 倍偏差仍存在。

主平面原生湿面积中位数 0.086704m²，明显大于作者切口 0.0431759m²，结合源内速度核对，说明本次原生过流截面扩张值得关注；没有隔离试验证明具体由哪个参数造成。源输水仅约 3 格厚，不能仅因几何厚度预检通过便声称流量精度通过。

此前上游 C 级可用 6cm 薄水截面积约 0.179726m²、速度 1.806m/s，容量估算 0.324593m³/s。本次原生中位数是其 **1.914 倍**；同面积要达该 Q，均速须约 **3.456m/s**。这不是现场水文测量，也不授权抬全上游河面。现有上游几何/流量没有与原生源匹配，JOIN 仍 **NOT_ASSEMBLED**。

## 三个开放面与收支可测范围

当前 fractions=False 的 `initDomain` 仍有外层 outflow 格：保留液体到删除层的实际 MAC 界面为 X− i1 / x−15.9250005、Y− j1 / y−16.9375004、X+ i319 / x7.9250005。采用外侧有 Outflow bit16、内侧没有 Outflow/Obstacle 的 gate，不用 flags==20 或整个矩形面积。Blender 官方 [grid.cpp](https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/extern/mantaflow/preprocessed/grid.cpp)、[grid.h](https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/extern/mantaflow/preprocessed/grid.h) 说明边界与 flags 编码；[extforces.cpp](https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/extern/mantaflow/preprocessed/plugin/extforces.cpp) 的 resetOutflow 及 [liquid_script.h](https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/intern/mantaflow/intern/strings/liquid_script.h) 的调用顺序解释删除后快照限制。独立审查代理已核对这些源码。
